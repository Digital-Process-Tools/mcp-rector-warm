Both self-review spawns (Explore reviewer and oss:auditor) independently converged on the same
finding against #131's fix (`src/Lsp/LspServer.php`, `runDueDiagnostics()`, commit 3cee9ac):

`runDueDiagnostics()` copies `diagnoseDocument()`'s `emit()`-based progress mechanics
(`$frames = []; $this->emit($this->progressCreate(), $frames); ...`) for cold-boot
`window/workDoneProgress` create/begin/end, but `runDueDiagnostics()` is declared `void` and never
returns or otherwise surfaces that local `$frames` array -- unlike `diagnoseDocument()`, which
returns its own `$frames` so a caller with no `frameWriter` wired (the "buffered" mode every
existing unit test used before this fix) still gets the progress frames back.

So whenever `canReportProgress` is true, `hasBootedOnce` is still false, and NO `frameWriter` was
supplied to the `LspServer` constructor, the create/begin/end frames for the debounced didChange
path are computed, pushed into a scope-local array, and silently discarded at the end of the loop
iteration -- never written anywhere, never observable to any caller. `hasBootedOnce` still flips to
`true` correctly, so a *later* diagnose (warm) correctly gets no progress; only the cold one's
progress notification is lost, not the bookkeeping.

Ranked by both reviewers as non-blocking: `bin/rector-warm-lsp` (the only production caller) always
wires a real `frameWriter` (confirmed by reading the constructor call there), so this branch is
unreachable in the shipped binary today -- the same "inert today, kept as defense-in-depth" shape
`diagnoseDocument()`'s own stale-result branch already documents elsewhere in this file. It has zero
test coverage in either direction: the new #131 test deliberately wires a real `frameWriter` to make
frames observable at all, and every pre-existing `LspServerBufferTest` test that calls
`runDueDiagnostics()` with no `frameWriter` never sends `initialize` with `workDoneProgress`, so
`canReportProgress` stays false and the buffering branch is never exercised either way.

What it would take to actually fix (not attempted here -- a design decision, not a one-line patch):
`runDueDiagnostics()` would need to return the accumulated frames (breaking its current `void`
contract and every existing call site, including `LspLoop.php:36-40`'s own callsite, which discards
the return today), or the buffered-mode combination needs to be documented as explicitly
unsupported/untestable rather than silently mirroring `diagnoseDocument()`'s docblock promise
("buffer it into $buffer for the caller to return") without actually keeping it at this call site.
This is recon's own "Open question 1" (already flagged before the fix was written) landing exactly
where it was expected to.
