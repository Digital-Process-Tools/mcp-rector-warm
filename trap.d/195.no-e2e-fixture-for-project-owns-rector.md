#195's fix (RectorRunner::projectShipsOwnRector()/ensureProjectAutoloaded(),
src/RectorRunner.php) is covered only by unit tests that call the two private/
protected methods directly via ReflectionMethod against a throwaway tmp
directory (tests/Unit/RectorRunnerTest.php). Nothing in tests/E2E or
tests/Fixtures exercises the real scenario -- a project with its own
vendor/rector/rector -- through the actual RectorTool -> RectorRunner::run()
-> bootInPlace() call path a real rector_process request takes. Confirmed:
`find tests/Fixtures -iname vendor -o -iname rector` finds no fixture with a
vendor/rector/rector directory anywhere in the tree.

The fix itself WAS verified empirically, but outside CI: tools/warm-vs-cold.py
against real laravel/framework v13.34.0 and symfony/symfony v7.4.20 checkouts
(each genuinely shipping vendor/rector/rector as a dev dependency), checkout
mode, went from 18/30 and 23/30 matching files to 30/30 on both after the fix,
with project-vendor mode staying 30/30 unaffected before and after. That
evidence lives in a PR body, not in anything CI replays.

What it would take to close the gap for real: a small fixture project (a
handful of files large enough that PHPStan's autoloader-driven resolution
differs from a pure-file-based scan) with a real, minimal Rector install
under vendor/rector/rector -- not just an empty marker directory, since the
regression this fix prevents is specifically "warm resolves a class/type
through the project's real Composer autoloader that cold never touches", and
proving that needs a real class only resolvable that way. Cheaper alternative
considered and rejected for this PR: an empty vendor/rector/rector marker
directory plus a fake vendor/autoload.php would prove the guard runs at all,
but not that skipping the autoload load leaves type inference unchanged --
that's exactly what the existing unit tests already prove more precisely
(via get_included_files()), so a fixture-based version would be redundant
with, not stronger than, what is already there. A real fixture with an actual
class resolvable only through Composer autoloading would be the version worth
having, and is a separate, larger piece of work than this fix.
