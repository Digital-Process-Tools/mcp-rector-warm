# #107: workspaceFolderListPaths() can't tell malformed from absent

What was observed: `LspServer::workspaceFolderListPaths()` returns `[]` both when a
client's `initialize` sends a `workspaceFolders` array containing malformed entries
(missing `uri`, wrong type, etc.) and when it sends none at all (or omits the field).
Both collapse to the same empty-array result and the same fallback behaviour
(single-root via rootUri/rootPath/--working-dir).

Where: src/Lsp/LspServer.php, workspaceFolderListPaths() (added in #107, commit 256ba2c).

Found by: oss:auditor spawned during #107's round-1 review. Classified as class A,
severity low, rank misreports/non-blocking -- the method's behaviour already matches
this file's own pre-existing "never crash on bad input" convention, just at a coarser
grain than a dedicated malformed-entries code path would give.

What it cost: nothing yet -- not fixed, since the auditor itself ranked it below the
maintainer's own blocking bar (CLAUDE.md rule 1: crash/hang/lost-edit/junk only). Logged
here instead of filed as an issue per that ranking.

How it was confirmed: read directly in the reviewer's pass over LspServer.php; no
test added either way since the behaviour is deliberate degradation, not a bug.

Unsure whether this is worth a dedicated "malformed vs absent" distinction at all, or
just an artifact of how permissive the fallback already is -- flagging for a later
curation pass to decide.
