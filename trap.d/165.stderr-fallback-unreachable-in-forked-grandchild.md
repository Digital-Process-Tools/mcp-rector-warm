Round-4 release-delta audit finding while fixing #165, in `RectorRunner::applySkipsOfOriginalPath()`
(src/RectorRunner.php, catch block around lines 2059-2071, docblock around lines 2010-2027).

The catch block itself already fails open SAFELY and correctly: it guards the stderr write with
`\defined('STDERR') && \is_resource(\STDERR)` before calling `\fwrite()`, so in the forked
grandchild path (`runForked()`, which has already closed fd 2), the write is simply skipped rather
than throwing a `TypeError` out of the catch and failing the whole call. The method's own inline
comment even explains this: "The forked grandchild has already closed fd 2 ... Write only where it
is open."

What is stale is the docblock ABOVE the method (around line 2025-2026), which still reads
approximately: "this fails open (the copy is diagnosed without those skips) and says so on stderr,
rather than failing the call." That claim is only true on the non-forked path. On the forked path,
nothing reaches stderr at all -- the fail-open behaviour is real, but "says so on stderr" is not, for
exactly the case the inline comment right above the fwrite() already documents accurately.

Not fixed here: out of scope for #165 (a different file, a documentation-accuracy issue rather than
a functional one -- the code's actual behaviour is already correct/safe). The fix is a docblock
wording change: either drop "and says so on stderr" from the class-level claim, or qualify it as
"where stderr is still open (the non-forked path)".
