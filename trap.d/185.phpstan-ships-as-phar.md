#185 (session-child dependency tracking): PHPStan -- and the BetterReflection fork
it bundles -- ships inside `vendor/phpstan/phpstan/phpstan.phar` (rector/rector
2.6.x pulls phpstan/phpstan 2.2.x). `grep -rl "class CachedParser" vendor/`
finds nothing, because the class is only reachable as
`phar://.../phpstan.phar/src/Parser/CachedParser.php`. The external prototype
hooked PHPStan by `require`-ing a patched copy of CachedParser ahead of the
autoloader. That works against a phar class too, but it ships a frozen copy of
vendor code that nothing re-checks after the next `composer update`.

What shipped instead decorates live service instances and patches no class.
`Warm\SessionHooks::installParserHook()` takes PHPStan's `pathRoutingParser`
service. Rector's own `config/phpstan/parser.neon` wires that service in as
`defaultAnalysisParser`, which is what FileNodesFetcher, FileTypeMapper,
TraitUseHandler and PhpClassReflectionExtension parse through. The hook wraps its
three private inner parsers (`currentPhpVersionRichParser`,
`currentPhpVersionSimpleParser`, `php8Parser`) in `Warm\TrackingParser` through
`ReflectionProperty`. The shape is checked at every session start:
`defaultAnalysisParser` must be the very same instance, and each property must
hold a `PHPStan\Parser\Parser`. On any mismatch the session disables itself and
the worker forks per call as before, so an upgrade that moves these services
cannot silently stop the tracking.

Also found while wiring it (Rector 2.6.x):
`RectorBetterReflectionSourceLocatorFactory` puts PHPStan's standard chain FIRST
and Rector's dynamic locator (the analysed file, then withAutoloadPaths) after
it. `DynamicSourceLocatorProvider::provide()` caches its aggregate on the first
call and ignores later `addFiles()`. So in any process that runs Rector twice,
the second call's own file is NOT in the dynamic locator. That is why
`WarmSession::route()` only lets the session analyse a file whose symbols the
standard chain or the autoload paths resolve to it, and declines the rest.
