Gate-3 release audit finding (v0.7.2..HEAD, round 1) on #189's DirectorySnapshot
(src/Warm/DirectorySnapshot.php:154-156 and :169-171):

When walk() cannot stat or list a directory, it returns without recording that
directory anywhere. firstChange() can therefore never report it, and
WarmSession::staleReason() reads the silence as "no change" -- nothing is
logged either.

What it costs (reasoned, not observed -- the suite was not run for this
finding): if a directory under a project root is unreadable when a warm
session spawns, and a class file later appears there, the session can keep
serving a memoised "class not found" while cold correctly finds the class.
Warm != cold, silently -- the exact defect class this repo's own CLAUDE.md
names as the oracle to protect.

Ranked non-blocking (misreports, not a destructive/chokepoint class): an
unreadable subdirectory at session-spawn time is an edge case, not the common
path, and the fix (DirectorySnapshot recording "could not read" as its own
third state alongside present/absent, and staleReason() treating that state
as "stale" rather than "unchanged") is a small API decision worth making
deliberately rather than rushed into this release.

How it would be confirmed: an E2E session scenario that chmod 000's a root
subdirectory before the session spawns, restores it, adds a class file inside,
and asserts the next call respawns instead of serving the memoised result.
