Round-4 release-delta audit finding while fixing #165, in `RectorDiagnosticsSource.php`
(isLinkOrJunction comment around lines 273-291) and `changelog.d/161.fixed.md` (lines 7-11, now
corrected as part of this same lane's #165 commit).

Both places claim `fopen($tempPath, 'x')` (`O_CREAT|O_EXCL`) "refuses unconditionally if anything --
file, symlink, or hard link -- already exists at $tempPath" and "closes the check-then-write TOCTOU
gap". That is true for a REGULAR file, a hard link, and a symlink whose target already exists (POSIX
`O_EXCL` refuses whenever a directory entry already exists at the given path, regardless of what it
resolves to). It is NOT true for a DANGLING symlink -- one whose target does not (yet) exist. Observed
directly in a scratchpad probe: `fopen()` on a path that is a dangling symlink returns a valid
resource, and the file that gets created lands at the SYMLINK'S TARGET, not at the symlink path
itself -- `fopen('x', ...)` follows the link to create the target rather than refusing because a
directory entry (the symlink itself) already exists there.

This is narrower than a reopened #149: the non-racy case (a symlink already present when the earlier
`isLinkOrJunction($tempPath)` check runs, a few lines above the fopen) is still caught by that check
regardless of whether the symlink is dangling or not, since `isLinkOrJunction()` uses `is_link()`,
which reports true for a symlink whether or not its target exists. The residual gap is a TOCTOU
window: a symlink appearing AFTER `isLinkOrJunction()` has already run and returned false, but BEFORE
`fopen()` reaches the path, and specifically one that is dangling at that moment. That is the same
family of gap as #145 (already filed, non-blocking) rather than a new, wider hole.

Not fixed here: out of scope for #165's own footprint (a comment/changelog accuracy issue plus a
narrow, already-tracked-family TOCTOU window, not the #165 fix itself). The changelog.d/161.fixed.md
inaccurate claim ("refuses unconditionally if anything ... already exists") WAS corrected in this
lane's own #165 commit, since it lives in a file this lane was already touching for the changelog
requirement; the source comment at RectorDiagnosticsSource.php:273-291 was left as-is to keep this
lane's diff to its own issue's footprint -- a maintainer or future lane should tighten that comment's
wording too.

non-racy case is fully covered, and the racy dangling-symlink case needs an attacker to win a very
