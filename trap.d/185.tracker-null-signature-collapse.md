Self-review finding on #185's DependencyFileTracker (src/Warm/DependencyFileTracker.php):
sig() returns null both when stat() genuinely fails right now (the file is gone,
permission denied, ...) and -- collapsed to the identical value -- when the path
was ALREADY unstat-able at record() time (so the stored signature was also null).
checkStale()'s `$current !== $signature` compares null against null and reports
"unchanged" for a path this tracker has literally never once been able to read
anything about, rather than surfacing that it never had anything to compare.

In practice this is narrow: record() is only ever called for a path a caller has
just successfully read (a hook handing it a path plus the hash of the bytes it
just parsed), so a stat() failure AT record() time is an edge case (a permission
change racing the read, a network filesystem hiccup) rather than the common
path. Ranked non-blocking (misreports, not a destructive/chokepoint class) --
recorded here rather than fixed, since the class is still unwired into any real
call path and the fix (distinguishing "never confirmed" from "confirmed
unchanged" as a third checkStale() state) is exactly the kind of small API
surface decision worth making once, when the real caller's needs are known,
rather than twice.

Update from the v0.8.0 gate-3 release audit (round 1): the premise above --
"the class is still unwired into any real call path" -- is now false. #189
wires DependencyFileTracker in: RectorRunner::serveSession ->
WarmSession::recordRead -> DependencyFileTracker::record()/checkStale(). Still
ranked non-blocking: record() is only reached for a path a caller has just
successfully read, so the stat()-fails-at-record-time collapse described
above stays an edge case rather than the common path, and there is no session
support on Windows (no pcntl) to widen its surface there. Re-rank against the
now-real call path before promoting this fragment; do not curate it on the
old "unwired" premise.

Further correction from the v0.8.0 gate-3 release audit, round 2: the round-1
update above kept this fragment's non-blocking rank on the premise that
"record() is only reached for a path a caller has just successfully read".
In the now-wired code that premise is false in three ways: (1)
WarmSession::watchedFiles (WarmSession.php:172-176, :186-189, reached from
RectorRunner::serveSession at :1370) deliberately records declared watch
files that do not exist yet; (2) TrackingParser reports before the read; (3)
no caller passes a real pre-read hash at all (see
trap.d/189.tracker-record-never-passes-toctou-hash.md). The non-blocking rank
still holds, but for a different reason: null-at-record is the designed path
for a not-yet-created watch file, and creating it correctly flips null to an
array, which checkStale() reports as stale. Re-rank against
RectorRunner.php:1370 -> WarmSession.php:186-189 -> record($path, null) on a
nonexistent path, not against either "unwired" premise recorded above.
