Release-auditor round-1 finding on the #179/PR #186 TempCopySweeper redesign (v0.7.2 gate 3,
ranked here as `misreports`, non-blocking).

What was observed: docs/lsp.md:66-73 still describes the removed startup behaviour -- that
each server removes leftover directories "at startup" once their owning "pid is no longer
running", and that "the startup walk goes 8 levels deep". PR #186 deleted `sweepTree()` from
bin/rector-warm-lsp and replaced pid-liveness checking with flock, so neither claim is true
after this release. The page also never tells an upgrading user that directories left behind
by 0.7.1 and earlier are no longer cleaned up automatically -- only changelog.d/179.fixed.md's
upgrade note says so. Stale code comments naming a "startup sweep" also remain at
src/Lsp/RectorDiagnosticsSource.php:237, :262 and :324.

What it costs: a reader of docs/lsp.md is told cleanup is automatic when, post-upgrade, old
leftovers are not swept.

Confirmed by: reading docs/lsp.md against the diff in PR #186 (bin/rector-warm-lsp,
TempCopySweeper.php) -- the docblock on TempCopySweeper's new design already states the
current behaviour correctly; docs/lsp.md just was not updated to match.

Fix, if picked up later: rewrite docs/lsp.md:66-73 to match TempCopySweeper's own docblock,
and refresh the three stale comments in RectorDiagnosticsSource.php.
