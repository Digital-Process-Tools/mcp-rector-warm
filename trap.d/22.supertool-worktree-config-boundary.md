supertool's raw-command guard and supertool's own op dispatch disagree about what
"this project" means for a git worktree that is nested under the main repo's own
directory (e.g. `.claude/worktrees/<name>`, as `git worktree add` here produces).

The PreToolUse hook that refuses a raw `git commit`/`git diff`/`git worktree unlock`
etc. walks the filesystem upward from cwd and found `<repo>/.supertool.json`
from inside the nested worktree -- so a raw `git
commit -m ...` run with `cd <worktree> && git commit ...` was refused there, pointing
at `supertool 'git-commit:...'` as the fix.

But `supertool 'cwd:<worktree>' 'git-commit:...'` (and `git-status`, `git-diff`, any
git-preset op) then refuses with "`.supertool.json` was found and could not be
loaded, so no preset ops and no project ops are loaded" -- supertool's own project
resolution is apparently bounded by the nearest `.git` (a worktree's `.git` is a file
pointing elsewhere, a separate boundary), so it will not walk past that boundary to
find the parent's `.supertool.json`, even though the parent directory literally
contains this worktree on disk and the hook found it fine.

Net effect: the raw form is refused, and the op that's supposed to replace it cannot
run either, for any git op, from inside this kind of worktree. `.supertool.json` is
untracked (confirmed via `git ls-files`), so it is never checked out into any
worktree on its own.

Workaround used here: `cp` the main repo's `.supertool.json` into the worktree root
before the git-preset call, then `rm` it again right after (it is not tracked, so
this never shows up in `git status`). Confirmed working for `git-status`,
`git-commit:@-` and `read`/`edit`/`paste` (though `read`/`edit`/`paste` worked fine
via `cwd:` even WITHOUT the copy present -- only the git-preset ops needed it, which
suggests the built-in ops resolve differently than the preset ones).

Not filed as an issue: no design decision needed, just a workaround that costs two
extra calls per git op inside this kind of nested worktree. Worth a rule if this
pattern (`git worktree add` under `.claude/worktrees/`) recurs.
