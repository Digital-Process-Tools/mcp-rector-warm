While verifying the exploit shape for a sibling finding (TempCopySweeper::lockIsFree), I tried a throwaway PHP probe script via `cat > /tmp/probe.php <<EOF`. The repo's own `python-heredoc-writes-are-unvalidated.md` jit-context rule blocks any `cat >`/`python3 - <<EOF` write pattern at command position, even for a disposable, non-project scratch file meant to be run once and discarded. The refusal message is correct and the fix is easy (`supertool 'cwd:<scratchpad>' 'paste:@-'` with a TOML `content` field), but it was not obvious on first read that a throwaway probe outside any tracked file still has to go through `paste:@-` rather than a plain heredoc -- the rule's own framing ("write a file into a checkout") reads as being about project files, not /tmp scratch. Confirmed by trying it, getting refused, then re-routing successfully through `supertool 'cwd:SCRATCHPAD' 'paste:@-'`.

Separately: a TOML triple-quoted literal content field containing PHP `"<?php\n"` needs exactly one literal backslash-n (not escaped further) to land as a 2-character PHP escape sequence on disk -- this worked correctly on the first attempt by following the existing jit-context guidance verbatim, but is easy to get wrong without that reminder already loaded.
