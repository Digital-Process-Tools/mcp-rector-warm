What was observed (self-review, oss:auditor pass on the killAndReap() extraction
commit, eb61542): killAndReap()'s WNOHANG branch (src/RectorRunner.php, taken only
when `function_exists('posix_kill')` is false) is reachable in principle -- it needs
pcntl present (so canFork() is true and boot()/runForked()/forkAndExecute() are
reachable at all) AND posix absent at the same time -- but nothing in this repo's test
suite or CI actually produces that combination.

Where: src/RectorRunner.php, killAndReap()'s else branch.

Why nothing currently exercises it: CI's `no-pcntl` job (.github/workflows/tests.yml)
disables exactly pcntl_fork/pcntl_waitpid/stream_socket_pair, which makes canFork()
false and routes everything through runCold() instead -- killAndReap() is never
entered on that leg at all, not even down the WNOHANG path. The regular matrix and e2e
jobs run with both pcntl and posix available, so `function_exists('posix_kill')` is
true there. The one existing test that manipulates posix_kill directly
(RectorRunnerTest::testDeadWorkerSelfHealsOnNextCall) skips itself when posix_kill is
UNavailable -- the opposite combination from the one this branch needs (pcntl present,
posix absent). No test or CI leg forces "pcntl present, posix absent" specifically.

What would settle it: a CI leg or unit test with `disable_functions=posix_kill` only
(pcntl left intact) would either exercise this branch for real or expose a mistake in
this reasoning about its correctness.
