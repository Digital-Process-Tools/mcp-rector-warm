#208 (replace inline @phpstan-ignore comments with code fixes) dropped
`self::assertIsArray($status)` from two tests after `$status =
proc_get_status($proc);` -- RectorRunnerStandbyWorkerTest.php and
RectorRunnerTest.php, each right before `$daemonPid = (int) $status['pid'];`
and a later `posix_kill($daemonPid, \SIGKILL)`.

Observed (independent audit, oss:auditor spawn, reasoned not run): the
assertion's own @phpstan-ignore (staticMethod.alreadyNarrowedType) said
PHPStan already proves $status is array here, same as several production
call sites of proc_get_status() this same PR deleted an is_array()/=== false
guard from (RectorRunner.php's cold-subprocess wait loop, stopOrphanWatchdog()).
Consistent with that reasoning, $proc is a still-open proc_open() resource
at this exact line in both tests (no proc_close() runs first), so under
today's code this is inert.

What it costs if the invariant is ever wrong (a future refactor, or an
environment where proc_get_status() genuinely returns false): the OLD code
failed loud with a clear PHPUnit assertion failure. The NEW code does not --
`$status['pid']` on `false` emits a PHP warning and evaluates to null, so
$daemonPid silently becomes 0, and the next line calls
`posix_kill(0, SIGKILL)`, which POSIX defines as "signal every process in
the caller's own process group" -- i.e. a SIGKILL across the whole CI
runner's process group, not a clean failure.

Not fixed in #208 itself: re-adding any array guard at this exact call site
reintroduces the same @phpstan-ignore the whole PR exists to remove (PHPStan
proves it redundant here, same as elsewhere in this PR), so fixing just these
two tests would be an inconsistent application of the issue's own mandate.
Ranked non-blocking (`fails-to-preserve`) by the auditor -- a test losing a
defense-in-depth assertion, not a behaviour change in shipped code.

Possible promotion: a jit-context rule for "a static-analysis-redundant
runtime assertion in a TEST can still be worth keeping, if what replaces it
on failure is a process-group-wide SIGKILL rather than a clean assertion
failure" -- i.e. test robustness and PHPStan redundancy are different axes,
and this repo should decide case by case whether to keep assertIsArray()-
style guards in tests specifically (with their own targeted ignore) even
after removing the equivalent guard from production code.
