Self-review finding (oss:auditor round) on the #73 fix, ranked `misreports` /
non-blocking per the findings table -- ships behind this fragment rather than
being filed, per the "can ship behind a trap.d fragment" row.

What was observed: `runCold()`'s no-pcntl deadline-poll loop (src/RectorRunner.php,
around the `proc_get_status()`/`proc_close()` branch fixed for #73) now prefers
`$procStatus['exitcode']` over `proc_close()`'s own return value, on the theory that
PHP only guarantees `exitcode` is valid on the FIRST `proc_get_status()` read after
the child stops running -- which is exactly the read this loop breaks on. That
theory was confirmed empirically on this machine's PHP 8.2.0 (POSIX): a real
`exit(7)` child polled the same way reports `exitcode: 7` from `proc_get_status()`
but `-1` from `proc_close()`, matching the bug #73 described.

The doc comment on the branch this fix lives in says it exists specifically for
"Windows, or #18's disable_functions case" -- i.e. the platform this whole
no-pcntl fallback is FOR is exactly the one platform this repo's CI never runs
(`.github/workflows/tests.yml` is `ubuntu-latest` only, all three jobs). Nobody
confirmed -- by reading PHP's own `ext/standard/proc_open.c`, or by running a
Windows leg -- that `proc_get_status()['exitcode']`'s "first read after exit is
valid" behavior holds identically on Windows as on POSIX PHP < 8.3. It probably
does (the PHP manual's own wording is not POSIX-scoped), but this fix's own
comment names Windows as a primary target and nothing here tests that target.

What it would cost to settle: either a Windows CI leg that runs
`testColdCallReportsRealExitCodeWithoutPcntl` (already forces the exact branch),
or a citation from PHP's own C source pinning the first-read semantics as
platform-independent. Neither was checked in this lane, which was working from a
macOS/Linux dev machine.

How it was confirmed: this is a reasoned (not observed) uncertainty, raised by
`oss:auditor` during self-review of PR closing #71/#73/#74, not something that
failed a test or broke a build.
