Self-review finding (auditor spawn, #134): `ProcessTree::parentOf()`
(src/Support/ProcessTree.php) returns `null` for two different reasons it
does not distinguish on POSIX: (1) the pid no longer exists (benign --
`bin/rector-warm-orphan-watchdog.php`'s own `ProcessTree::isAlive($workerPid)
=== false` check just above already handles that case and exits), and (2)
`ps` itself could not be run at all (`ProcessTree::run()` returns `null`
whenever `proc_open`/`ps` is unavailable -- a minimal/scratch container image
with no `ps` binary, for instance).

The watchdog's own fallback for a `null` parent is
`\PHP_OS_FAMILY === 'Windows' && ProcessTree::isAlive($daemonPid) === false`
-- on POSIX that expression is unconditionally `false`, so in case (2) the
watchdog treats "could not tell" as "not orphaned" forever, sleeps, and
retries with the identical result every single poll. #134's whole fix --
the daemon-liveness watchdog killing an orphaned worker mid-call -- goes
silently inert in that one environment: no error, no log line, nothing a
maintainer could see short of the call itself eventually finishing (or a
totally unrelated `--call-timeout`).

Reasoned, not observed: the auditor did not have a container image with no
`ps` binary and no way to spawn one available to actually run
`testTheStandbyExitsWhenItsDaemonIsKilledMidCall` against; neither did this
lane. Ranked by the auditor as `fails-to-preserve`, non-blocking per
skills/manager/phases/findings.md's own table ("can ship behind a trap.d
fragment"), which is why this is here rather than a code change or a filed
issue.

What a real fix would need: a THIRD state out of `parentOf()` --
"pid gone" vs "could not tell" -- rather than folding both into `null`, so
the watchdog can treat "could not tell" as "stay alive, keep polling" (which
it already effectively does) while somewhere making the degraded state
observable (a log line, a distinct exit code, something). Left for whoever
curates this: is that worth a dedicated third return value, or is a `ps`-less
POSIX container rare enough that "best effort, no signal" (matching
ProcessTree's own class docblock philosophy) is an acceptable, simply
undocumented, limit here too.
