RESOLVED (#96 lane, same PR #104 round). The next step above was followed:
`.github/workflows/tests.yml` (commit 26973bb) added `--display-warnings` to the
CI phpunit invocation, and that made the withheld detail block visible on the
very next windows-latest run:

    1) tests/Unit/RectorRunnerTest.php:1154
    rmdir(...Temp/rector-runner-cold-timeout-test-8e7bdd3b46e7d266): Resource
    temporarily unavailable
    Triggered by: RectorRunnerTest::testColdCallIsKilledAtItsDeadlineWithoutPcntl

So it was neither the `\r`/ANSI theory nor a PHP-level E_WARNING/E_DEPRECATED --
a genuine Windows delete-in-use race: `rmdir($tmp)` in that test's `finally`
races the OS still holding the just-killed cold subprocess's handle on $tmp,
its own working directory at the moment it was killed (TerminateProcess() on
Windows does not release file handles as synchronously as POSIX's kill does,
and RectorRunner::runCold()'s deadline-poll kill path does not itself wait for
handle release before returning). Only line 1154 (`rmdir($tmp)`, the outer dir
that was the child's cwd) warned, not line 1153 (`rmdir($tmp . '/src')`, a
subdirectory the child never chdir'd into) -- consistent with this theory.

Fixed by a `rmdirWithRetry()` helper (10 attempts, 100ms backoff, matching
runCold()'s own poll interval) wrapping both rmdir() calls in that test's
`finally` block. See trap.d/96.windows-rmdir-race-fixed.md for the fix record.
