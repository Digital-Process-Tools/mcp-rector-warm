- Fixed (#72): `rector_process` now refuses a `dryRun:false` call while a `--call-timeout` deadline is active, before the call ever starts. Every kill site the #58 deadline added (`RectorRunner::killAndReap()`, the worker backstop, the no-pcntl `proc_terminate()` path) sends an unconditional SIGKILL/signal 9 with no grace for an in-flight file write; Rector writes each changed file by truncating it and then writing the new content, so a kill landing mid-write could leave that file truncated with no copy of its original content anywhere. A dry-run call never writes, so it stays unaffected and keeps running under an active deadline exactly as before. To apply changes (`dryRun:false`) under a deadline that could kill the call, restart the server with `--call-timeout=0` (unlimited, the pre-#58 behaviour) -- the caller now gets a clear `rector_process: refusing dryRun:false ...` error instead of a silent risk of data loss.
