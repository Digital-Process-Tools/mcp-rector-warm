- Fixed (#58): a genuinely wedged warm call (not merely a slow one) now fails after a configurable `--call-timeout` (default 600s, 0 = unlimited) instead of blocking the caller forever. PR #57's own fix for #32 (retry a socket-read timeout forever instead of mistaking it for the worker dying) had no upper bound of its own, so a truly hung analysis regressed from "errors after ~60s" to "never returns." The killed analysis's grandchild process is reaped so it never lingers as a zombie, the worker itself stays up and serves the next call normally, and the no-pcntl `proc_open` fallback gets the same deadline via `proc_get_status()`/`proc_terminate()`. The E2E scenario added for this fix is the "list the daemon's children after the call" check #48 asked for as its own settling criterion. See the README's Options table for `--call-timeout`.
